# Hosted remote and CI for the merge gate: November 2026

Checked 2026-11-27. This file is agent research for [proposal 0008](../../docs/proposals/0008-hosted-ci.md) and decides nothing. It collects facts on running OVC's merge gate off the owner's laptop:

- hosted forges with CI;
- self-hosted runners on a virtual server in Russia;
- Russian forges;
- what the gate needs.

Prices, quotas and policies are volatile, so recheck them on the provider's own page before ordering anything. No account was created, nothing was pushed, and no service was contacted beyond reading public pages.

## Method and conventions

- Sources are official provider pages and documentation unless marked **third-party**. A fact that no reachable page confirmed is marked **unverified**. An arithmetic result is marked **calculated**.
- An inference from a source's wording rather than a direct statement is marked **inferred**.
- Ruble prices include VAT where the provider says so. Russia's general VAT rate is 22% from 2026-01-01, as the [November hosting recheck](hosting-and-services-prices-2026-11-23.md#vat) records.
- A month is 720 hours. "A gate" is one run of `tools/merge-gate.sh` with the full local check run.

## 1. What the gate needs

These facts come from the repository on 2026-11-27, not from external pages.

- **Checks.** The gate runs the full local check run of the [development guide](../../docs/development.md#change-checks-and-the-merge-gate):
  - `go test -race` over the backend, the Go static checks and `govulncheck`;
  - Gitleaks, OSV-Scanner and the documentation checks;
  - the frontend type check, lint, unit tests and build;
  - `pnpm e2e`, with Playwright in Chromium, Firefox and WebKit, against the production build and the real backend and worker.

  Three lanes run at the same time, and the end-to-end suite runs alone last ([ADR-0018](../../docs/decisions/0018-targeted-checks-and-merge-gate.md#decision)).
- **Services.** The gate needs Docker with two containers, both pinned by digest in `docker-compose.yml`: PostgreSQL (`postgres:18.6`) and SeaweedFS (`chrislusf/seaweedfs:4.48`) as the S3-compatible store. It also needs the pinned tools of `bin/`, built from `tools/go.mod`.
- **Time.** Recent full-run gates take about 600 to 670 s of wall time on the owner's laptop, which has 12 cores and 24 GB of memory. NFR-6.2 and ADR-0018's check budget set 600 s as the hard limit. The end-to-end suite uses 6 workers.
- **Volume.** About 15 to 20 gates a day when several sessions work in parallel, as the coordinator reports. At 600 to 670 s a gate, that is about 150 to 223 minutes of gate time a day, or about 4,500 to 6,700 minutes a month at 30 days (**calculated**).
- **Exclusivity.** ADR-0018 requires a full-run gate to start on an idle machine: one-minute load below 6 and no other check or build running. The gate holds a per-user merge-gate lock and the end-to-end run lock, and gates run one after another. So today, while one gate runs, no other heavy run can happen on the laptop.
- **Platform.** The laptop runs macOS, and Linux is also a supported development platform (`AGENTS.md`, Platforms). Playwright's WebKit on Linux is a different build from Safari's engine on macOS. A Linux gate host may therefore expose failures the laptop does not, and the reverse.

### GitHub and users in Russia

- **Trade controls.** GitHub's trade-controls policy lists Russia among the destinations to which GitHub Enterprise Server and Copilot may not be sold or exported ([trade controls](https://docs.github.com/en/site-policy/other-site-policies/github-and-trade-controls)). The account-level suspension of private and paid services that it describes applies to Crimea and the other regions it names, not to Russia as a whole.
- **Account suspensions.** In March 2022 GitHub said its free services stay available to developers in Russia ([GitHub blog](https://github.blog/news-insights/company-news/our-response-to-the-war-in-ukraine/)). In April 2022 it suspended accounts linked to sanctioned companies, and some were later restored. This is **third-party** and was read through search summaries only: [Cointelegraph](https://cointelegraph.com/news/github-suspends-accounts-of-russian-developers-linked-to-sanctioned-firms), [Habr](https://habr.com/ru/news/661321/).
- **Payment.** No official page on paying GitHub from Russia was found. Russian guides of 2026 say cards issued in Russia are declined, and some of those guides sell workarounds (**third-party**, **unverified**; for example [Marix](https://marix.app/library/guides/github-copilot-russia-2026)). A paid plan or overage is therefore likely hard to pay. Free with self-hosted runners avoids payment, but has no enforced required checks on a private repository.

## 6. Data residency under ADR-0008

- **What ADR-0008 requires.** [ADR-0008](../../docs/decisions/0008-hosting-and-data-residency.md) requires every component that stores or processes user data to be in Russia, and forbids sending personal data to services abroad.
- **What the repository holds.** Source code, documentation, synthetic test fixtures and the public legal texts. It holds no user data: there are no production users, and secrets are never committed (`AGENTS.md`, Security).
- **What a gate run produces.** Only synthetic data: seeded test accounts, the database mail sink, the fake meeting provider and local storage. Its logs follow the [observability rules](../specs/observability.md#safe-content) and hold no secrets.
- **Conclusion.** A CI service abroad would receive code and synthetic logs, not personal data, so ADR-0008 does not forbid it. A gate host in Russia avoids the question entirely.
- **Settings.** The gate currently loads the owner's environment files through `tools/dev-env.sh`. A remote gate needs its own test-only settings, generated on the host for each run; no owner environment file may be copied there.
- **Runner logs.** A runner connected to GitHub sends job logs and artifacts to Microsoft and Amazon storage (section 3). Placing a self-hosted runner in Russia does not change where its logs go.
- **Suspension.** If GitHub suspended an account because of sanctions, the remote and its CI would be cut off, but the work would not: Git keeps the full history in every checkout.

## 7. Mapping ADR-0018's gate to hosted CI

| ADR-0018 rule | Required checks or merge queue | A gate host that runs `main`'s `tools/merge-gate.sh` |
|---|---|---|
| The tested tree is the tree `main` will hold, and the finishing step proves `main^{tree}` equals it | Pull-request checks run on GitHub's test merge commit, and with strict mode and fast-forward merges the head tree equals the merged tree (**unverified** in detail); either way the check result belongs to a commit GitHub built, not to a tree the merging machine recorded. A merge queue tests the combined tree, but needs Enterprise Cloud on GitHub, Premium on GitLab, or Pro or Enterprise on GitFlic | The laptop keeps the lock, records the base and the tested tree, sends that tree as a bundle and checks the commit and tree the host reports; the merge and `finish` stay on the laptop, so `finish` checks the same equality as today |
| `main`'s copy of the gate script runs, so a change cannot weaken its own gate (T-41) | A push-triggered workflow runs the workflow file of the pushed commit, so a change can edit its own checks. A dispatch from `main` that takes the candidate commit as input keeps the workflow on `main`, provided the workflow checks `github.ref`, since anyone with write access can dispatch it from another branch (**inferred** from GitHub's event model) | Unchanged: the host runs `main`'s copy from a scratch folder |
| Idle machine and exclusive locks | A hosted runner is a fresh machine per job; a self-hosted runner needs one job at a time | One gate per host at a time. The laptop's load no longer matters, but a host with shared vCPU still has noisy neighbours |
| On macOS no lane command can reach the gate's result pipe; on Linux one can through `/proc` (ADR-0018, T-41) | Results are reported by the runner, which the candidate's code runs on | The same Linux weakness; a separate recording user, `hidepid` and a restricted `ptrace_scope` narrow it, and a throwaway machine per gate confines a forged result to its own run |
| One gate per merge, gates in sequence | A merge queue gates queued changes speculatively and in parallel | Several hosts allow parallel gates. Each stays valid only while `main` has not moved, unless candidates are stacked in merge order |
| Reruns only for a named infrastructure error; every attempt logged | "Re-run jobs" buttons make repeated attempts easy; the run history keeps every attempt | The gate's attempt log stays; runner and network failures join the named infrastructure errors |
| The 600 s budget is measured on the gate's wall time | Hardware changes with the runner size | The budget is re-measured on the reference host |
