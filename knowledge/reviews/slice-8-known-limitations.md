# Slice 8 known limitations

Status: agent record, started 2026-11-10. Minor review findings of slice 8 changes that were accepted rather than fixed, in the format of the numbered slices' files. Each entry is re-verified by the slice review, which resolves it as fixed, accepted by the owner or carried into a named later slice.

| Finding | Severity | Change | Why it was accepted |
|---|---|---|---|
| Each template autosave reserves two rate-limit rows (`template_saves_second` and `template_saves_hour`) in their own committed step under the tutor's profile lock and then takes the profile lock again for the save, so an open builder costs up to two such pairs of short transactions per second. | Minor (performance risk) | S1, the library and builder contract | The pattern is the one lesson writes use and is bounded by the two-per-second limit; the backend reviewers of B4 and the slice review check the per-save cost, and measurements wait for the deployment by the owner's decision of 2026-11-08. |
| The presentation's 5-minute signed storage URL may stay in the self-hosted conferencing server's own logs, while the credentials-in-URLs rule of `AGENTS.md` says such URLs are never logged; OVC itself never logs or stores it. | Minor | S1, the library and builder contract | The URL stops working after 5 minutes and grants one file only; the residual is recorded in T-11 and the presentation section, pending owner review, and the remote BigBlueButton activation decides that server's log hygiene. Accepted by the owner on 2026-11-10 as a residual risk. |
| The refusal, rate-limit, discard and acceptance events of the upload pipeline still carry the chat channel attribute from the open upload, which only the channel scope fills, and the refusal and rate-limit events carry no context; an upload of a context without a channel scope would log a zero `channel_id`. | Minor (observability) | B2a, the upload pipeline made context-driven | No context other than chat reaches the pipeline in B2a, so chat events are unchanged; B2 gives the library contexts their own scope attributes and event fields when it adds them, and its reviewers check them against the observability specification. Resolved in B2 (`feat/library-uploads-and-tokens`), for the slice review to confirm: every upload record carries `context`, `channel_id` appears only for chat uploads, and `TestLibraryUploadKinds` asserts that no library upload record carries a `channel_id`. |
| Library uploads share the general limits of 4 concurrent uploads per user and 32 per instance with chat: a 100 MB library upload may hold its slot up to the 10-minute read deadline while it delivers at least 16 KiB in every 30 seconds, so eight confirmed tutors uploading four slow files each can hold every slot of an instance and make chat uploads answer `429` until those uploads end; only the durable intent capacity is separate by class. T-20 records the general slow-upload residual but not this library case. | Minor | B2, library uploads and download tokens | The limits are the specified ones (D20) and need confirmed tutors; the slot hold is bounded by the read deadline and the stall rule; naming the case in T-20 changes `docs/`, which needs the owner's review, so it is carried to the slice review. |
| The kind authorizations of `GET /attachments/{id}` and `GET /files/{id}` are an interface (`referenceAuthorization`) with an empty list in the files service, so the minting and serving paths of version 2 have no authorized kind and the `ref` refusal at `422` cannot be reached end to end in B2; only unit tests cover the parser and the token layout. | Minor | B2, library uploads and download tokens | The plan stages each kind's authorization into the change that creates its table; B3 decides how the material authorization is registered and adds the end-to-end refusal-order and serving tests. Resolved for the `material` kind in B3 (`feat/library-folders-and-materials`), for the slice review to confirm: the files service registers the material authorization, and `TestAttachmentMintRequiresReference` and `TestPictureMaterialsAreDownloadedThroughTheirMaterial` reach the `422` at `ref` and the serving re-check end to end; the `template` and `lesson` kinds stay refused until B4 and B5. Resolved for the `lesson` kind in B5 (`feat/lesson-materials`): the files service registers the lesson authorization, and `TestLessonMaterialAfterLibraryDeleteStillDownloads` and `TestLessonMaterialsVisibility` mint and serve it end to end. |
| The Firefox end-to-end test `upload transport › an expired multipart upload refreshes once, removal aborts, and changing accounts clears a held upload` (`frontend/e2e/upload-transport.spec.ts:170`) sometimes counts two `POST /api/v1/auth/refresh` responses instead of one at its assertion `expect(replayRefreshes).toBe(1)`, while the replayed upload's statuses are `[401, 201]` as expected; it failed one merge gate run of B2. Run alone in Firefox with `--repeat-each` on 2026-11-10, it failed 4 times in 300 runs on the B2 tree and 1 time in 300 on `main` at `c372969`, with the same assertion, so the flake predates B2, which changes no frontend or authentication code. | Minor (flaky test) | B2, library uploads and download tokens (found, not caused) | A flaky test is a bug under `AGENTS.md`; its cause (presumably a second refresh racing the replay after the 16-minute clock advance) is outside B2's scope, so it is recorded for a fix in a separate change before the slice review, which confirms it. |
| A restricted-Markdown link may show a trusted-looking address as its label while pointing elsewhere (`[https://good.example](https://evil.example)`), look-alike IDN hosts are kept (only punycoded in the `href`), and `https` links to loopback or private addresses are kept; T-14 in the threat model records this residual for chat but not yet for Markdown links. | Minor | F1, the frontend Markdown renderer | The renderer applies the specified `https`-only rule and opens links with `noopener noreferrer`; recording the residual in T-14 changes `docs/`, which needs the owner's review, so it is carried to the slice review. |
| The renderer's link check uses `URL.parse`, which needs Safari 18, Chromium 126 or Firefox 126 or later; on an older browser the call throws and the page fails closed without rendering anything unsafe. | Minor | F1, the frontend Markdown renderer | The supported browsers are the current versions of each, which all provide `URL.parse`; the dependency is recorded here for the browser review of the slice. |
| Text normalisation version 1 can expand a name or title up to about 18 times in code points and 11 times in bytes (for example U+FDFA under NFKC), so a 100-code-point folder name or a 200-code-point title can normalise to more than PostgreSQL's B-tree tuple limit of about 2,700 bytes on the `normalised_name` and `normalised_title` indexes, which would answer an internal error instead of a validation error. | Minor | B1, text normalisation version 1 | The rule is pure and has no storage of its own in B1; B3, which creates those columns and indexes, bounds the normalised byte length with a `422 validation_failed` refusal or proves with a test that the worst case inserts. Resolved in B3 (`feat/library-folders-and-materials`) by the owner's choice of 2026-11-10, for the slice review to confirm: a folder name normalising to more than 400 bytes or a title to more than 800 bytes answers `422 validation_failed` `too_long` (`TestLibraryTextLimits`, `TestFolderNamesAreUniqueAmongSiblingsAndValidated`), and check constraints hold the same bounds in the database; B4 applies the title bound to templates. |
| Number parsing version 1 runs on the text normalisation result, so NFKC turns superscript, enclosed and fullwidth digits into ordinary ones: `1²` parses as 12, `①` as 1, `１，５` as 1.5. | Minor | B1, number parsing version 1 | This is what the specification's order of steps defines; a student's literal typing of such characters is rare, and a later rules version may refuse them without re-scoring stored answers. |
| Text normalisation version 1 keeps zero-width and other invisible characters (U+200B, U+00AD) and does not unify lookalike letters across scripts (Latin `a` and Cyrillic `а`), so two folder names that look identical can coexist and a search can miss. | Nit | B1, text normalisation version 1 | The specification defines exactly these steps; the effect stays within one tutor's own library or one student's own answer, and a later rules version may strip format characters. |
| `ClaimExpiredUploads` selects expired pending uploads in a subquery and locks them `FOR UPDATE SKIP LOCKED` without re-checking `state = 'pending'` in the outer query, and the expiry's `MarkAttachmentDeleted` matches any state other than `deleted`, so a binding (a chat send or, from B3, a material creation) that commits between the expiry statement's snapshot and its row lock at the 24-hour boundary could have its just-bound file marked deleted and its object deletion queued. | Minor (pre-existing, unverified) | B3, library folders and materials (found, not caused) | The pattern predates slice 8 and applies to chat as well; the window is the instant of the 24-hour boundary; the fix belongs to the upload expiry, outside B3's scope, and the slice review confirms or refutes it with a race test. |
| The library listing's keyset cursor carries the last item's normalised title in plain base64url in the `cursor` query parameter, so a title can reach a reverse proxy's records if they keep query strings. | Nit | B3, library folders and materials | OVC's access records name route templates only and `q` already travels in the query by the specification; an opaque or signed cursor can replace it later without a contract change. |
| The domain's `TemplateBlock` keeps block, option, material and image identifiers as canonical strings, the stored JSON shape, rather than named identifier types; the checker parses each at the boundary and stores its canonical form, and the service matches stored identifiers to rows by their string form. | Minor | B4, library templates | The strings are validated and canonicalised by `CheckTemplateBlocks` before anything is stored, and the parsed material and image identifiers it returns are typed; a typed stored shape can replace the strings without a contract change. |
| A template item of `GET /library` carries the material-only fields `width`, `height`, `url` and `expires_at` as `null`, while `homework.md` lists them only for materials. | Nit | B4, library templates | A client parses items by `kind`, and the generated schema marks the fields nullable; removing them from template items changes the shared `LibraryItem` schema, which F2 can do with its parser if it wants. |
| Folder and material routes of B3 accept the alternative UUID spellings that huma's `format: uuid` allows (braced, URN, 32 hex digits) in `parent_id`, `folder_id` and `attachment_id` and then answer `500` because the domain parser takes only the 36-character form; B4's template bodies add a strict pattern and answer `422`. | Minor (pre-existing) | B4, library templates (found in B3's routes) | No client sends those spellings; the same pattern can be added to the B3 schemas in a follow-up that also changes the generated client. |
| `TestTemplateAutosaveBeyondHourlyWriteLimit` makes 700 real saves but seeds the library write counter to 599 instead of making 599 real writes before the 600th and the refused 601st. | Nit | B4, library templates | The seed proves the same boundary (no save counted toward `library_writes_hour`, the 600th write succeeds, the 601st answers `429`) without 600 extra requests in the full run's budget. |
| Minting a `lesson` reference reads every lesson that holds a live reference to the attachment and that the caller sees (`VisibleLessonReferences`), so for the tutor the cost of one mint grows with the number of occurrences sharing a file, at most about 12,100 future lessons plus past ones per tutor. | Minor (performance risk) | B5, lesson and series materials | The reference authorization interface of B2 returns every visible item before it checks `ref`; narrowing it to the requested item changes the shared mint path that B4 also extends, so it waits for the slice review, and measurements wait for the deployment by the owner's decision of 2026-11-08. |
| `POST /lessons/{id}/materials` on a lesson that is not `scheduled` sends `entity.changed lesson` to every student on the frozen roster, including one whose link is `reclaim_pending` and who cannot see the lesson; the frame carries only the lesson identifier. | Nit | B5, lesson and series materials | It follows the realtime specification's roster recipients and the existing frozen-roster signalling, and reveals no more than the identifier the student already received. |
| `bodyIdentifierDenialCases` has no row for `material_ids` in `POST /lessons/{id}/materials` and `PATCH /lessons/{id}` with `following`, and the reclaim-pending, discarded-link and ended-relationship cases of lesson-material minting are proven by `TestTheStudentVisibilityCopiesAgree` rather than inside `TestLessonMaterialsVisibility`. | Minor (coverage) | B5, lesson and series materials | The behaviour is asserted by `TestLessonMaterialRefusalsAndTheirOrder` (another tutor's material like a random identifier on every path) and by the agreement test over the whole visibility world; the table keys one denial case per route, and `POST /lessons` already holds its audience case. |
| A split without `material_ids` moves the series' references to the new series without `file.reference.added` or `file.reference.removed` records, because the same attachments are added and removed in one transaction. | Nit | B5, lesson and series materials | No charge or file changes; `series.split` records the split. |
| `TestEditOfAFinishedSeriesComparesTheLessonsMaterials` proves the edit rule for a finished series only for a counted series; the end-date branch of `seriesRetired` (no occurrence weekday left before the end date, or the end date already past) is proven by the retirement tests of the hourly run, which use the same predicate in SQL, but not through an edit. | Minor (coverage) | B5, lesson and series materials | The Go and SQL predicates were compared case by case by the re-review; an edit test for the end-date branch can be added with the frontend change F4's lesson dialog cases. |
| The shared fake's tests of an unfetchable presentation (a refusal, a redirect, an oversized file, a held response) and of the origin refusal serve the presentation from an in-process `httptest` server instead of the local S3-compatible server; the oversized case streams the 100 MB library limit plus one byte over loopback on each run. | Minor | B6, the lesson presentation | The server stands for the conferencing server's view of an arbitrary storage origin, which in-process servers may play; the local S3 server cannot produce a redirect or a held response on demand, and the fetch from real storage through a real presigned address is proven by `TestFakeMeetingReceivesPresentation`. The slice review may move the cases that real storage can produce (a refused signature, an empty and an oversized object) onto it. |
