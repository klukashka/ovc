## Integration and authority

The realtime client's discriminated new-message event retains the already parsed positive safe-integer sequence. The existing per-query-client coalescer keeps its one-second scheduled cadence, list-first-page/unread behavior and channel-detail refresh. Read updates schedule list/unread work only. A small mounted-owner registry forwards known live intent without importing the lazy history implementation into the eager frame.

The lazy `historyRefresh.ts` owner retains a sequence high-water and at most 100 unique dirty message identifiers, using the API's existing maximum-page size as the metadata cap. Overflow requests full reconciliation and clears the dirty set; it does not drop the required changes. New rows come only from authorized REST after_seq pages of at most 100, continuing until the captured sequence is covered. A gap, empty progress, missing snapshot or inconsistent identified row falls back to full reconciliation. Edits/deletions of cached rows use after_seq=known_seq-1 with limit=1 and validate the returned identifier and sequence, including tombstones and complete attachment metadata. IDs outside displayed history create no fabricated row.

One lease barrier serializes incremental reads, the default full query and actual older-page loading. A full lease remains held until TanStack publishes its result/error or cancels/removes the query; the HTTP promise alone does not release it. Fallback releases the live lease before awaiting invalidation, avoiding a query queued behind its own caller. Full reads clear older intents they cover; events arriving after their start retain follow-up work. A new frame received after a full query starts requires a fresh catch-up request even if that queued full query subsequently includes its row. The captured fresh-read intent prevents a sequence already present in cache from suppressing that mandatory follow-up. The existing FollowingQueryClient fresh-read behavior remains intact and no mutable query-function mode is introduced.

The default query always rereads every displayed page. Initial/first-ready/reconnect, channel-scope or unclassified invalidation, Retry, conflict recovery and signed-file renewal remain full authoritative reads. Reconnect cannot recover an old edit/deletion with append-only catch-up. Older-page merging and incremental publication preserve the oldest continuation cursor and descending cached/ascending rendered ordering. Read markers still derive from visible rendered rows and versions.

Operation scope revisions are captured per read, not permanently at mount, because the revision is global and an unrelated channel can advance it. Epoch and channel-query identity remain lifetime guards; incremental cancellation generations reject cancelled work. A connected-event cancellation discards/aborts owned incremental work without aborting an existing shared full query, preserving its mandatory authoritative follow-up. Full queries recheck current ownership, request signal and operation scope before returning data for publication. Unmount/account/scope loss cannot recreate removed history. Existing unavailable notice, draft, explicit conflict-version adoption and attachment refresh behavior remain intact.

The narrow FakeChat held-history fixture returns the already authorized no-store REST snapshot unchanged after release. It introduces no protocol route, transport replacement or fabricated response. Its contract check compares the held response to an independent real fake-adapter read. Existing auth/scope checks still occur before the history branch. The threat-model addition maps T-18/T-19/T-20/T-21/T-29/T-36/T-41/T-44 and is pending owner review; it grants no authorization.
