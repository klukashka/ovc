# Slice 3 known limitations

Minor findings accepted during slice 3 instead of starting another review round ([ADR-0011](../../docs/decisions/0011-tiered-verification.md)). The slice review re-verifies each entry; each is fixed, accepted by the owner or carried into a named later slice.

| Finding | Severity | Change | Why it was accepted |
|---|---|---|---|
| The student list and its search read and sort all of a tutor's matching cards for every page, because the `state = ANY(...)` filter keeps PostgreSQL from using `relationships_tutor_list_idx` for the ordering | minor | Student cards and invitation links | The work is bounded by one tutor's cards; the slice review's performance pass measures the query plan on 50,000 relationships, and an index on `(tutor_id, created_at DESC, id DESC) WHERE state <> 'discarded'` is the likely fix |
| During the 30 days before a deleted student's purge, an ended card still shows that student's account name and email to the tutor | minor | Student cards and invitation links | This matches the current specification, which shows the linked account on `provisional`, `active` and `ended` cards until the purge; whether a deleted account should be hidden earlier is to be decided explicitly under [T-34](../../docs/threat-model.md) at the slice review |
| Signed-in acceptance reads the account email used for the card's email binding before its transaction, outside the account's row lock | minor | Signed-in acceptance and My tutors | Safe while no account email change exists (email change is outside the MVP); when one lands, the binding check moves under the account's row lock |
| The reclaim expiry failure-isolation tests make one account fail through a trigger created in the test database, which refuses to clear the deadline for one email prefix, and the join-request expiry failure-isolation tests (`TestJoinRequestExpirySkipsFailingRequestsAcrossTheBatchBoundary`, `TestJoinRequestExpiryResumesPastPersistentFailures`) likewise refuse the expiry of the requests of one email prefix through a trigger, by the owner's decision of 2026-10-23; it is a real database refusal, not a replaced code path, but the testing rules list fakes as the only test doubles | minor | Reclaim choice; join requests | Accepted for the slice review to re-verify against the testing rules; the alternative is a constraint or a fault-injecting fake behind an injected interface |
| Two endings of the same relationship in the same microsecond, with a reactivation between them, share the `relationship.ended` idempotency key `(relationship.ended, relationship, ended_at)`, so the second email is not queued | minor | Ending relationships | Practically unreachable: an ending, a reactivation and a second ending cannot all commit within one microsecond on the system clock; it shows only with the fake test clock, whose tests advance it between endings |
| The ending services read `now` before their transaction, so a second ending that waited on the relationship lock while a reactivation committed can record an `ended_at` earlier than that reactivation | minor | Ending relationships | Practically unreachable and harmless: the window is the lock wait of one request; the ended state, the email and its obsolescence check all use the stored `ended_at`, so only the recorded time is slightly early |
| The Node runtime pinned by `frontend/.node-version` (26.0.0) bundles undici 8.0.2, which the advisories accepted in `frontend/osv-scanner.toml` also affect; no lockfile scan sees it, and the end-to-end harness's built-in fetch uses it against the local deployment only | minor | Undici advisories in the test tools | Node does not run in production, where the frontend ships as static files; the slice review checks for a Node 26 release bundling a fixed undici |
| One large tutor purge can take a whole run's budget of 100 batch transactions, so the accounts behind it in that run wait for the next hourly run (head-of-line delay) | minor | Deletion effects on tutoring | The delay is bounded: each run moves the large purge forward by 50,000 rows, and the accounts behind it are purged once it finishes; the slice review's performance pass measures it, and a per-account share of the budget is the likely fix |
| A tutor's deletion through `DELETE /users/me` runs its discard, ending, revocation and expiry statements over all of the tutor's relationships, invitations and requests in one transaction, without a bound | minor | Deletion effects on tutoring | The work grows only with the tutor's own cards, which grow by at most 50 a day plus the cards that removals give; the slice review's performance pass measures the request on 50,000 relationships |
| A second stale refusal in a row on the student card's End dialog refocuses the page-level notice through a remount keyed by a refusal counter, but no test covers two refusals in a row: jsdom has no `HTMLDialogElement.showModal`, and in this change an active card offers no dialog action after the first refusal | minor | Invitation and reclaim pages | The single-refusal end-to-end test covers the focus move; the groups and End dialog change, which gives an active card the End dialog, adds a two-refusal end-to-end test |
| The journey end-to-end tests (`join-requests.spec.ts` pilot and My tutors journeys, `account-edge-cases.spec.ts` FR-1.3 role mismatch, `accessibility.spec.ts` busy save) interleave act and assert steps after the first act instead of three distinct Arrange–Act–Assert phases, as the earlier journey specs of slices 1–3 do | minor | Join requests and My tutors pages | A pilot scenario is a sequence of user steps whose intermediate states are the acceptance criteria; the slice review decides whether AGENTS.md records a journey-test exception or the journeys are split into per-step tests |
| The join-request row buttons mark every row unavailable while a decision runs but set `aria-busy` on none, so the button that started the decision does not announce that it is busy | minor | Join requests and My tutors pages | The specification does not require a busy announcement, the decision notice takes focus when it completes, and the slice review's browser pass decides whether the deciding button tracks its row |
| `scripts/eslint-rules.test.ts` › `rejects importing vi` timed out once at 5000 ms in a unit-test run started right after the lint run, and passed on rerun and in every later run | minor | Join requests and My tutors pages | Observed once under load in a file the change does not touch; the slice review's tooling pass measures the test's run time and fixes its cause if it recurs |
