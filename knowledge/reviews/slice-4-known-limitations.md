# Slice 4 known limitations

Minor findings accepted during slice 4 instead of starting another review round ([ADR-0011](../../docs/decisions/0011-tiered-verification.md)). The slice review re-verifies each entry; each is fixed, accepted by the owner or carried into a named later slice.

| Finding | Severity | Change | Why it was accepted |
|---|---|---|---|
| During the transition to the per-user end-to-end run lock, a worktree whose branch still carries the earlier harness takes the old per-checkout lock in its own `frontend/test-results/e2e-run.lock` and does not contend with the per-user lock in the user's cache folder, so it can run at the same time as a run on the new harness and share the per-worker ports and the `ovc-e2e` bucket with it | minor | Per-user end-to-end run lock | The window closes once every active worktree has merged `main` after this change; until then, sessions start an end-to-end run in an older worktree only after merging `main` into it |
| No test proves that a failed clock read ends a run; a failed claim and a failed retry update are tested | minor | Per-lane worker loops | The system clock that the continuous loops use never fails to read, and `Tick` uses the instant it is given; a failed clock read while claiming takes the branch of the tested failed claim, and one while completing takes the branch of the tested failed retry update |
| A panic in the worker's own claiming code after a claim committed leaves the rows it had not yet started `in_progress` until their 5-minute lease expires, and they are then sent; the lane records the panic, stops claiming, lets its started effects finish and ends the run | minor | Per-lane worker loops | It needs a programming error in the claim path; delivery stays at least once and no row is lost |
| No test makes `LISTEN` itself fail, so the listener's `listen` loss kind is covered by reading only; provoking it needs a real database error on a fresh connection, which no supported test technique produces without altering the database | minor | Realtime signals and listener | The path shares the connect failure's handling, which the silent-listener test exercises through the forwarder; the slice review re-checks it |
| The revocation-trigger migration's `Down` section is never run by a test; no migration's `Down` is, project-wide | minor | Realtime signals and listener | By inspection it drops the three triggers before their functions; a project-wide down-migration test is a separate change |
| `TCP_USER_TIMEOUT` on the listening connection is compiled and linted for Linux but not exercised, because development and test machines run macOS | minor | Realtime signals and listener | Loss detection does not depend on it: the self-heartbeat detects a silent connection within 5 seconds, which the forwarder test proves |
| The listener-test forwarder resolves the checked database host again when it dials, instead of dialing the address it checked | minor | Realtime signals and listener | Test-only code against a loopback host the fixture has just verified; a host name whose resolution changes between the check and the dial within one test is not a realistic test environment |
| A direct call of the listener-test forwarder's `Stop` waits for a write already in progress, so it would block if a peer stopped reading with full socket buffers; the test cleanup closes the connections first and cannot block | minor | Realtime signals and listener | The only caller, the silent-listener test, stops the forwarder while the listener keeps reading; waiting for the in-flight write is what makes the stop exact in both directions at once |
