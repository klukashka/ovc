# Slice 4 known limitations

Minor findings accepted during slice 4 instead of starting another review round ([ADR-0011](../../docs/decisions/0011-tiered-verification.md)). The slice review re-verifies each entry; each is fixed, accepted by the owner or carried into a named later slice.

| Finding | Severity | Change | Why it was accepted |
|---|---|---|---|
| During the transition to the per-user end-to-end run lock, a worktree whose branch still carries the earlier harness takes the old per-checkout lock in its own `frontend/test-results/e2e-run.lock` and does not contend with the per-user lock in the user's cache folder, so it can run at the same time as a run on the new harness and share the per-worker ports and the `ovc-e2e` bucket with it | minor | Per-user end-to-end run lock | The window closes once every active worktree has merged `main` after this change; until then, sessions start an end-to-end run in an older worktree only after merging `main` into it |
| No test proves that a failed clock read ends a run; a failed claim and a failed retry update are tested | minor | Per-lane worker loops | The system clock that the continuous loops use never fails to read, and `Tick` uses the instant it is given; a failed clock read while claiming takes the branch of the tested failed claim, and one while completing takes the branch of the tested failed retry update |
| A panic in the worker's own claiming code after a claim committed leaves the rows it had not yet started `in_progress` until their 5-minute lease expires, and they are then sent; the lane records the panic, stops claiming, lets its started effects finish and ends the run | minor | Per-lane worker loops | It needs a programming error in the claim path; delivery stays at least once and no row is lost |
| No test makes `LISTEN` itself fail, so the listener's `listen` loss kind is covered by reading only; provoking it needs a real database error on a fresh connection, which no supported test technique produces without altering the database | minor | Realtime signals and listener | The path shares the connect failure's handling, which the silent-listener test exercises through the forwarder; the slice review re-checks it |
| The revocation-trigger migration's `Down` section is never run by a test; no migration's `Down` is, project-wide | minor | Realtime signals and listener | By inspection it drops the three triggers before their functions; a project-wide down-migration test is a separate change |
| `TCP_USER_TIMEOUT` on the listening connection is compiled and linted for Linux but not exercised, because development and test machines run macOS | minor | Realtime signals and listener | Loss detection does not depend on it: the self-heartbeat detects a silent connection within 5 seconds, which the forwarder test proves |
| The listener-test forwarder resolves the checked database host again when it dials, instead of dialing the address it checked | minor | Realtime signals and listener | Test-only code against a loopback host the fixture has just verified; a host name whose resolution changes between the check and the dial within one test is not a realistic test environment |
| A direct call of the listener-test forwarder's `Stop` waits for a write already in progress, so it would block if a peer stopped reading with full socket buffers; the test cleanup closes the connections first and cannot block | minor | Realtime signals and listener | The only caller, the silent-listener test, stops the forwarder while the listener keeps reading; waiting for the in-flight write is what makes the stop exact in both directions at once |
| Inbound frames are decoded with Go's JSON decoder, which matches keys case-insensitively and keeps the last of duplicate keys, so `{"TYPE":"ping"}` is accepted although the contract refuses unknown properties | minor | WebSocket gateway | Frames carry no authority beyond the token, which is verified in full, and a differently cased key cannot reach any other behaviour; an exact-key decoder is a small follow-up the frontend contract test of F1 can drive |
| `TestNoFrameIsDeliveredWhileARecheckIsPending` proves the absence of a frame during a held re-check by waiting 300 ms after the delivery record, not by an explicit condition | minor | WebSocket gateway | The frame is queued under the gateway's lock while the socket is suspended, and an unsuspended writer would write it within milliseconds; the frame's arrival in order after the release is asserted explicitly |
| `TestEveryFrameTypeHasAGatewayTest` checks that a named test exists for each frame type and close code, not that the test produces it, and maps `1000` to a client-initiated close | minor | WebSocket gateway | Each named test asserts its frame or close code itself; a runtime registry of produced frames would need hooks in production code |
| `TestSlowConsumerIsClosedWith4429` accepts a client-side close without a status, because the close frame cannot reach a client that stopped reading, and asserts `4429` from the gateway's close record; it publishes a fixed 10,000 frames instead of publishing until the close | minor | WebSocket gateway | The gateway's record is the authoritative close code; the fixed volume is far above the queue bound and the test waits for the record with a deadline |
| A frame queued for a socket just before the gateway itself closes it (a pong or an error frame before a flood or protocol close) may be dropped instead of written before the close frame | minor | WebSocket gateway | The close code states the reason, and the client reconnects and refetches; no frame of another account is affected |
| Without a gateway in its options, the WebSocket route answers `503 service_unavailable` after the origin and upgrade checks; only test harnesses construct the API without one | minor | WebSocket gateway | The production composition always passes a gateway; the answer keeps the route's refusal order intact in the audience test |
| `POST /notifications/read` with `through` marks read a row whose `created_at` precedes the named row but whose producer committed after the caller's list was shown, so that row is marked read without having been shown | minor | In-app notifications | Accepted in the slice plan (D14): the window is one producer transaction, the row's `notification.new` still arrives so the client refetches and lists it as read, and closing the gap would need a commit-ordered sequence that serialises producers |
| No test races an un-suppression that frees a request of an account being purged against that purge, which the purge's order (the rows naming the account are deleted after the user row, whose deletion cascades to the join requests) guards; the concurrent-producer test races a decline | minor | In-app notifications | Unreachable today: a purgeable student's requests are expired at deletion or held while unconfirmed, and confirmation is serialised with the purge by the user row lock; the order is shown correct by reading the statements under read committed |
| A tutor whose accepted join request led to a card that later ended still learns from `label_deleted: true` on the `join_request.created` row that the student deleted their account, for up to the 90-day retention; T-34's residual names only a block or a card the student ended earlier | minor | In-app notifications | It follows the owner's rule for `label_deleted` (D43); the tutor already sees the same through the card's null account, and recording the case in T-34 is a `docs/` change for the owner |
| The end-to-end check that lazily loaded chunks are requested only after a token left the address reads the address from Playwright's request handler, a round trip after the browser started the request, so it proves the address was clean before the chunk could run but not before it was requested | minor | Route-level code splitting | Component tests prove deterministically that each token holder renders nothing below it, and so requests no page module, until the address is cleared; the bundle check keeps the holders in the first load; an exact in-page observer would need a hook into module loading |
| The `access-gate` first-load chunk imports the frames from the entry chunk, which imports it in turn, so the two chunks form an import cycle; it is safe while the Gate module reads no entry binding at its top level | minor | Route-level code splitting | Rolldown's `strictExecutionOrder`, which removes the cycle, adds 3.4 KB gzip to the 180 KB first-load budget that F1's realtime client still has to fit in; a top-level read would fail the start-up of every page, which every end-to-end test would show, and it fails closed: no page chunk loads |
| `lazyPage` creates a new page module and key on each call, so it is correct only when called once per route outside rendering; nothing enforces that | minor | Route-level code splitting | Every call is at module scope in `router.tsx`, where the route table is built once; a call during rendering would only restart the import and remount the route, never load a page before the access rule or the token holders |
