# Design slice known limitations

Status: agent record, started 2026-11-08. Minor review findings of design slice changes that were accepted rather than fixed, in the format of the numbered slices' files. Each entry is re-verified by the slice review, which resolves it as fixed, accepted by the owner or carried into a named later slice.

| Finding | Severity | Change | Why it was accepted |
|---|---|---|---|
| On the notifications page, a row's link is named only by the event's one-line text, so a page can hold up to 30 links with the same name, such as "New join request"; the label sits in the next cell. | Minor | Step L1, the desktop layout standard | Inside a table each link is read with its row, and the event text never interpolates a name by design ([states](../design/web/states.md#notifications)); adding the label to the link name with `aria-describedby` is a cheap later improvement. |
| A tutor's bio is clamped to two lines in My tutors, and its full text is offered visually only through the `title` tooltip, which keyboard and touch users cannot open; screen readers read the whole bio. | Minor | Step L1, the desktop layout standard | `pages.md` specifies the clamp with the tooltip; a "Show more" for the bio is left to the phone layouts of slice 10 or a later review. |
| Names that are the row's link in the Students and Groups tables are cut with an ellipsis on one line and have no tooltip, as they were before the tables. | Minor | Step L1, the desktop layout standard | Unchanged behaviour of these lists; the full name is on the card or group page the link opens. |
| A refusal of sign out everywhere showing inside its dialog and taking focus is verified by reading the code only (the shared `FormAlert` focuses itself on mount); no end-to-end test forces the refusal, because the real backend cannot be made to refuse `POST /auth/logout-all` without a fake or a forbidden interception. | Minor | Step L2, Settings on the layout standard | The busy state is covered by a test that holds the request with the allowed hold-then-continue form; the refusal path reuses the alert every other settings form already uses. |
| The test that Cancel on sign out everywhere revokes nothing reloads the second browser in its assert phase to prove that browser is still signed in. | Minor | Step L2, Settings on the layout standard | The reload is the observation itself: the second browser's access token lives only in memory, so only a reload through the refresh cookie shows that its session survived. |
| Every `relationship` and `channel` frame now invalidates the open calendar at once, outside the chat coalescer, so a burst (an ending sends one `relationship` frame and one `channel` frame per shared channel) starts one calendar request per frame. | Minor | Step D2a, Today | The count is bounded by the number of channels the two people share, and the plan accepts the card-edit case; folding the calendar into the coalescer's wave is a cheap later change. |
| Below 1280 px Today stacks the main column above the side column, so the checklist and today's lessons, which load after the first render, push the join requests and the tutor code down. | Minor | Step D2a, Today | The join-request panel's "nothing moves" rule is kept on computers, where the columns sit side by side; phone layouts are designed in slice 10. |
| Today keeps its own "Deleted user" text instead of the chat's, because the chat texts load only with Messages and Today must not pull that chunk into its first load. | Minor | Step D2a, Today | Two strings of the same meaning are cheaper than a larger first load. |
| The focus moves when a read behind Today's checklist or unread messages fails (focus moves to that panel's heading; the "All messages" link stays while earlier data is shown) are verified by reading the code only; no end-to-end test forces such a failure, because the real backend cannot be made to refuse those reads without a fake or a forbidden interception. | Minor | Step D2a, Today | The row-removal focus moves that share the same hook are covered end to end; the failure path reuses it. |
| Home's handling of a calendar refusal of its `tutor` value (`404`, `422`) is verified by reading the code only: the page refuses any value no current tutor holds before calling the calendar, so the end-to-end tests prove that no calendar request carries such a value, and the server's refusal is reached only in a race with a tutor list that changed meanwhile. | Minor | Step D2b, Home | The stronger client-side refusal is tested; the race path shows the same notice. |
| Home computes its next lesson and its seven-day window when it renders, so a lesson that ends while Home stays open stays "Next lesson" until the next render or refetch. | Minor | Step D2b, Home | Step D6 brings the room timers to Home, which re-render it with the lesson's phases. |
| On a computer, Messages subtracts only the frame's padding from the window height, so while the offline banner or the email confirmation banner is shown the document scrolls by the banner's height, and a long upload queue or the edit-conflict panel can shrink the history pane. | Minor | Step D3, Messages | The banners are temporary states; fitting them needs the frame to become a full-height column for one route, which is a frame change for slice 10's layout work. |
| No test asserts that a provisional student's choice button in the New lesson dialog is named by the name alone with "Email not confirmed" as its description. | Minor | Step D4, New lesson dialog | The naming is set by `aria-labelledby` and `aria-describedby` on one component; a test needs a provisional card in the dialog's search, which no current dialog test seeds. |
| No test proves that the week keeps the reader's scroll position on a live refetch of the same week; component tests run without the stylesheet and cannot scroll. | Minor | Step D4, Schedule | The effect runs only for a new week start, which the opening tests and code review cover. |
| After Change clears the choice, a preselected audience that the results do not list stays under the heading "Chosen" although nothing is chosen. | Minor | Step D4, New lesson dialog | The row is the way to choose it again; renaming the shared "Chosen" label also changes the end series flow's wording, which belongs to a separate wording change. |
| No test exercises the reset of an unedited group title to "Lesson" when Change clears a group. | Minor | Step D4, New lesson dialog | The reset is the same call the dialog makes on choosing; the end-to-end Change test uses a one-to-one student. |
| A refused notes save shows only "Notes were not saved.", not the refusal's reason (for example an invalid character or a rate limit with its wait), which the earlier form's refusal text showed. | Minor | Step D5, student card | The text and "Try again" stay; the reason can be added with the shared refusal text in a later wording change. |
| The card's and the group's "Saved." notice after a dialog edit stays on the page beside the notes' own "Saved." status, so two status regions can show the same word. | Minor | Step D5, student card and group page | Each region is announced once when it changes; the page notice is the dialog's focus target. |
| The end-to-end autosave tests check the number of saves and the stored notes, not the request body, because Chromium does not expose the body of the frontend's `fetch` requests to Playwright; that the body holds only `notes` is proved by the component test against the fake server. | Minor | Step D5, student card | The component test exercises the same request code. |
| Dismissing "End working together" opened from the card's menu, the group dialog's stale close and the archive refusal alert have no focus test of their own; they use the shared dialog and notice components whose focus rules other tests cover. | Minor | Step D5, student card and group page | Covered by shared components; tests can be added with the slice review. |
| The group page's archive and unarchive sentence keys stay in the language files unused. | Minor | Step D5, group page | Removing keys belongs with a wording change. |
| Several Join buttons on Today carry the same name ("Join lesson") with no reference to their lesson, so a screen reader user moving through them hears the lesson only from the neighbouring row link. | Minor | Step D6, Today | Overlapping join windows are rare; describing each button by its row needs the shared action button to accept a description. |
| Home's next lesson is chosen by its scheduled end, so a `live` lesson that runs past its end stops being the next lesson and loses Join on Home (the lesson page still offers it), and a lesson ended early stays the next lesson until its scheduled end. | Minor | Step D6, Home | The selection predates step D6; changing it touches Home's ordering rules. |
| No test proves that "Room opens at {time}" moves to the following row on Today when one row's window opens, and the end-to-end `not_found` tests on Home do not assert the focus move, which the component test proves. | Minor | Step D6, Today and Home | The behavior comes from the same clock and focus code the component tests cover. |
| Three component tests of the Join control each prove several offers by rendering more than once in their arrange phase. | Minor | Step D6, tests | Each keeps one act and one assert phase; splitting them is a test refactor. |
| `students.spec.ts` › notes typed and reloaded before the save keep nothing in storage once raised a page error in WebKit whose text the redacted diagnostics did not keep. | Minor | Step D5, student card | Not reproduced in 15 runs; recorded in the WebKit failure record for slice 10's WebKit diagnosis. |
| No test drives Home's first-read failure of the next lesson's room state to its load failure and Retry. | Minor | Step D6, Home | The branch reuses the shared load failure component; a test needs a refused detail read for one lesson. |
| No test asserts the lesson page's "Messages" link in its new place in the header, for either role; none asserted it in the page body before. | Minor | Step D7, lesson page | The link's condition and address are unchanged; a check can be added with the slice review's browser pass. |
| That a notice or a refetch failure never remounts the lesson room rests on the page's fixed tree, which code review checked; the tests prove only the start passing and the controls leaving. | Minor | Step D7, lesson page | The room's ancestors take no part in those states; the two tests cover the transitions that do change the header. |
