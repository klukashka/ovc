# Slice 1 deferred findings

Minor findings from the readiness reviews of the slice 1 backend and frontend scaffolds that were accepted for later rather than fixed in the change itself. The file ships with the frontend scaffold because that change is the first after the backend scaffold to add review records. The slice 1 review re-checks each one and either fixes it, schedules it in a named slice, or closes it with a reason.

| Area | Finding | Proposed resolution |
|---|---|---|
| Test database fixture (`backend/internal/testdb`) | A failed `CREATE DATABASE` or connection reports the pgx error text, which can include the admin URL with its password redacted by pgx but still names user and host. | Wrap fixture errors in a message that names only the operation and the database. |
| Test control guard | The loopback `Host` check accepts a bare `localhost`, which is safe only while no other local name resolves there. | Decide whether to keep `localhost` or require an IP literal, and record the decision in the harness section of the development guide. |
| Theme preference (`frontend/public/theme-init.js`) | The `system` theme applies `prefers-color-scheme` once at load and does not follow later changes of the scheme, although [tokens](../design/web/tokens.md#theme-selection) says `system` follows it. | Add a `matchMedia` change listener together with the theme setting in slice 2. |
| Production headers | The page headers in `frontend/security-headers.ts` must be reproduced by the production reverse proxy, which is recorded only in prose. | When the deployment is built, generate the proxy header block from `security-headers.ts` or run the smoke's header assertions against the deployed origin. |
| Playwright traces | `trace: 'retain-on-failure'` records network traffic and storage under the ignored `frontend/test-results/`; once sign-in lands, failing traces will hold test passwords, tokens and join links. | Decide in slice 2 whether traces stay on, and record that they are local-only test artefacts. |
| Tailwind classes | An unknown utility class (for example a token name that is not in the theme) produces no CSS and no error, so a missing token goes unnoticed. | Add a check that rejects class names Tailwind does not generate. |
| Comment checks | `.env.example`, `.gitignore` and `.toml` files are not covered by any comment check, and the root `.gitignore` has comment lines. | Extend the conventions test to these files and remove the existing comments. |
| Frontend icons | Icons are 16 px at every width; [tokens](../design/web/tokens.md#illustration-and-iconography) asks for 20 px on phones. | Size icons from a token with the phone layouts in slice 10. |
| Sidebar overlay focus | When a browser closes the overlay dialog natively without its `cancel` step, the frame does not return focus to the show button itself and relies on the browser's own restore, which in Safari can land on `body`. | Return focus on the native `close` event unless a route change moved it, and cover it in the slice 10 accessibility pass. |
| Test control tick and the worker clock | With `OVC_TEST_CONTROL=1` and `OVC_CLOCK=system`, `POST /__test__/tick` runs a tick at the shared test-clock instant inside the API process while the worker's own loop runs on system time. | Decide in slice 2, with the first outbox job, whether the routes require `OVC_CLOCK=test` or tick at system time, and specify it in the development guide and the notifications specification. |
| Transport deadlines and the clock | The per-request read and write deadlines are computed from the injected `Now`, which is the system clock in every process today. | Keep transport deadlines on the system clock if a test clock is ever passed to the API handler. |
| Error code schema | `ErrorBody.code` is a plain string in the OpenAPI document, so the frontend cannot type-check its translations of error codes. | Publish the codes as an enum in slice 2, when the frontend first translates them. |
