## First change L1: typed provider contract and local fake

Outcome: a deterministic, explicitly injected meeting provider can execute its local lifecycle contract without PostgreSQL, BBB, cloud credentials or a network outside loopback. No API routes, schema migrations, join button or provider-call worker wiring are added in L1. Persisted meeting rows and all lesson authorization belong to L2; do not expose an unguarded local substitute as a user feature.

Files proposed:

- backend/internal/domain/meetings.go: named meeting/provider identifiers, create-time value, participant role and opaque participant identifier, provider status and typed result data. Add only types used by L1.
- backend/internal/adapters/meeting/provider.go: MVP CreateMeeting, MeetingInfo, JoinLink and EndMeeting interface consistent with the video contract; no recording methods or library/presentation implementation. Provider link is a sensitive type with explicit access and redacted fmt/slog/JSON/text representations, reusing the existing core.Secret machinery where appropriate rather than duplicating redaction; never an ordinary loggable string.
- backend/internal/adapters/meeting/fake.go: constructor-injected time, randomness and bound logger; synchronized per-instance state with an explicit configured capacity, no package globals, environment reads, background goroutines or wall-clock synchronization. Cancellation is checked under synchronization immediately before the atomic state transition; cancellation after that linearization point does not roll back a completed transition. Creating an already-existing identical provider meeting reuses its identity; inconsistent duplicate input is refused. End and repeated end have explicit idempotent outcomes. Link creation does not itself imply participant entry.
- backend/internal/adapters/meeting/contract_test.go and fake_test.go: reusable provider contract test cases and explicit fake-only simulation controls. Public simulation operations for entry, departure or a named provider failure are part of the configured fake implementation, never runtime patching. A synthetic join address is not exposed by application routes or navigated externally; its bounded fake redemption operation checks binding to the opaque participant identifier, role and meeting generation/create-time. An unknown link or tampering with any bound field is refused without mutating state; this is fake credential integrity, not lesson authorization. Do not claim this proves BBB token lifetime, duplicate-user policy or browser media behavior.
- knowledge/architecture/detailed.md: explicit new package/layer entry and module description; no dependency additions.
- knowledge/specs/realtime-and-video.md: distinguish MVP interface, local fake simulation, sensitive links and still-unverified provider-specific semantics. Resolve naming differences before implementation, without changing the server authorization rule.
- knowledge/specs/observability.md: adapter-owned fixed event names, levels and permitted fields; no fake business-authorization or lesson-live events and no INFO message on each successful MeetingInfo poll.
- docs/development.md, docs/threat-model.md, the ordering records above, knowledge/plans/slice-7-local-foundation.md and knowledge/reviews/slice-7-local-foundation.md.

Keep implementation small: no HTTP fake room, production BBB endpoint settings, migrations, frontend or generic fault-injection framework in L1. The fake's simulation controls are limited to the cases named here. Bound meeting/link and per-meeting participant state with constructor configuration; repeated redemption of a valid link is allowed within the same meeting and must not accumulate unbounded connection records. Bound meeting/link state with constructor configuration and release owned state on end; retain only the minimum generation information necessary to reject stale links, also bounded. The exact overflow behavior is a typed provider failure, not silent eviction of active meetings. Capacity is a fake resource bound, not a new production admission policy.

## Checkable acceptance

- TestMeetingProviderContract: CreateMeeting returns a stable create time; MeetingInfo distinguishes absent and created; JoinLink does not mutate created into running; EndMeeting reaches absent; repeated end is idempotent. Deterministic assertions exercise the actual fake implementation, not mocked calls.
- TestFakeMeetingLifecycle: explicit entry/leave simulation produces running/created state; ending revokes current generation links; a new generation cannot redeem an old link even when the injected clock is frozen and the same provider identifier is recreated. Use a per-instance monotonically unique bounded generation counter independent of wall time; reject overflow with a typed failure. Check repeated valid-link redemption without growing the participant set.
- TestFakeMeetingIsolationAndBounds: separate instances do not share meetings, invalid roles/unknown meetings and tampered participant/role/generation bindings fail without state mutation, configured meeting/link caps fail explicitly, end releases owned bounded resources, no raw participant names or link values appear in captured structured diagnostics.
- TestFakeMeetingCancellationAndConcurrency: operations canceled before entry or while waiting for the synchronized transition do not mutate state; cancellation after a completed atomic transition does not imply rollback; parallel create/info/link/end operations preserve invariants under go test -race; use barriers, not sleeps.
- TestMeetingLinkRedaction: formatting, structured logging and error paths never reveal the synthetic credential. Explicit consumer access is separate and tested.
- Architecture/conventions checks enforce package layers and source rules; no new dependency, public route, frontend build output or recording behavior is introduced.

The shared contract initially runs only against the fake. BBB shared-contract execution remains unverified until a remote adapter and host exist. Provider-specific behaviors that the probe may overturn remain marked as simulation choices, not newly certified BBB contracts.
