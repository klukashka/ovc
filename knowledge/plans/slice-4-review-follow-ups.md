## Changes in order

Measurements that are acceptance criteria run one at a time on an otherwise idle machine, never beside another change's checks.

1. **`fix/tutor-deletion-signal-batching`** (backend; security trigger met: purge and deletion). Tutor deletion sends its one signal per relationship in one `pg_notify` statement per chunk. Threat model: T-34 and T-29 unchanged in substance; the change records nothing new. Acceptance: a committed test asserts that the number of `pg_notify` statements of a tutor deletion does not grow with the number of relationships; `TestTutorDeletionSplitsItsSignalsAndLocksNoStudentRow` and the realtime delivery tests pass; the deletion measurement at 50,000 relationships is repeated on an idle machine and recorded.
2. **`fix/blocked-students-in-join-request-unsuppression`** (backend; security trigger met: authorization and scope). `UnsuppressJoinRequests` and `CountVisiblePendingJoinRequests` exclude requests of operator-blocked students, as `ListTutorJoinRequests` does. Threat model: T-33 gains that requests of operator-blocked students produce no notification row, frame or count for the tutor, and that after an operator's unblock the request is un-suppressed only by a later decision that frees a slot. Acceptance: a subtest of `TestBlockStateNeverReachesTheStudent` asserts no row, no `notification.new` or `entity.changed` frame and an unchanged visible count for a blocked suppressed requester, and the behaviour after an unblock.
3. **`fix/realtime-and-token-hardening`** (backend; security trigger met: rate limits, tokens in links, test infrastructure). The per-address socket limit reuses the sign-in throttle's address bucketing (IPv4 and IPv4-mapped addresses unmapped first, IPv6 by /64); unsubscribe tokens refuse any byte outside the base64url alphabet and decode strictly, so trailing bits make no second spelling; an unsubscribe racing the purge answers `422 token_invalid`; the heartbeat is sent on the listener's own connection instead of the pool. The forwarder's end-of-stream relay is its own branch, `fix/listener-forwarder-end-of-stream`, because it changes the text of an `AGENTS.md` exception: a half-close in the other direction is a faithful relay of the stream, and `AGENTS.md`, ADR-0009 item 8 and T-41 say so in that branch, with the owner's review. Threat model: T-20 records the /64 bucketing; T-32 records strict token decoding and the purge answer; T-20 or T-29 records that the heartbeat no longer competes with requests for the pool. Acceptance: one named test per item, including an IPv4-mapped peer counted as its IPv4 address and two IPv6 addresses of one /64 sharing one budget; a test that a held pool does not delay the heartbeat.
4. **`fix/frontend-slice-4-review`** (frontend; security trigger met: the session's token handling). The panel's Retry keeps focus in the open panel and Escape still closes it; a failed background or live refetch of a loaded student card or group page keeps the data and shows a non-replacing notice; the reconnect refetch also refetches queries in error; the `beforeunload` listener goes, leaving `pagehide`; the token check uses wall-clock time; after a `1012` close the client waits a jittered delay of at least the listener's reconnect delay before reconnecting; the reconnect test waits for the request only after the socket count went to 0 and back; the notification tests seed their rows in a worker-scoped fixture. Threat model: T-2 or T-29 records the wall-clock token check and the jittered reconnect. Acceptance: `toBeFocused` tests for the panel; a component test that typing survives a failed refetch; a unit test of the reconnect refetch with an errored query; a unit test that a token is treated as expired by wall-clock time across a paused monotonic clock, through the injected scheduler; a test that no `beforeunload` listener remains; the mass-reconnect measurement repeated on an idle machine after changes 3 and 4, recorded with full recovery under 15 seconds as the pass mark.
5. **`chore/checks-after-slice-4-review`** (tooling; security trigger met: dependencies, the served build, secrets scanning).
   - The release-age check parses both workspace files with a YAML parser added as a direct development dependency of the frontend (recorded in the stack table), refuses duplicate keys, checks the parsed `minimumReleaseAge` and `minimumReleaseAgeExclude`, and refuses the setting in a `.npmrc` or the `pnpm` field of `package.json` of either folder.
   - `check:bundle` allows in `dist/` only the files of `public/` that Git tracks and only the asset files the build manifest names, and refuses dotfiles.
   - The end-to-end harness forgives a cancelled request only for a navigation that started after the request; the socket-slot helper asserts that the page's own socket was refused.
   - The Gitleaks allowlist narrows from the whole file to the variable-name pattern of the start-up refusal tests; a finding in history that the narrower rule then reports gets a dated triage, never a wider rule.
   - Threat model: T-39 records the YAML-parsed check and its refusals; T-41 and T-27 record the tracked-files and manifest-named-assets rule; T-19 records the narrowed allowlist.
   - Acceptance: a unit test of each new refusal (flow list, unindented list, decoy line, duplicate key, `.npmrc`, `package.json`, untracked `public/` file, dotfile, unnamed asset); Gitleaks over history and staged changes passes, and a test string in that file that matches a secret rule but not the pattern is reported; the end-to-end suites unchanged in count.
6. **`docs/slice-4-review-records`** (documentation; security trigger met: agent configuration and the threat model; `docs/` wording pending owner review). Runs after the forwarder branch of change 3. `docs/development.md` describes the keep-alive proxy and the request-failure rule; the forwarder branch of change 3 already corrected the package path to `internal/testdb/forwarder` in `AGENTS.md`, ADR-0009 item 8, T-36, T-41 and the realtime specification, so change 6 only confirms it; T-20's residual says a stolen token's sockets also end when the session is revoked; T-38 records the shared keep-alive proxy connections, excluding upgrades; the `label_deleted` and the keep-alive rows of the slice 4 known limitations close.
7. **`chore/e2e-consolidation-after-slice-4`** (tooling; the security trigger is assumed met if the harness or the test control surface changes). After changes 1 to 6, the end-to-end suites are consolidated without dropping coverage, every key refusal and authorization test keeping its own assertion: the reviewers named the per-scenario tutor seeding of the realtime contract suite and the three join-request focus tests as candidates, and B0's shared actors extend to further read-only tests. Acceptance: a check-budget record of a cold run on an idle machine, the security scans included, at 180 seconds or less; slice 5's 149-second target of D46 is reported against it, and if either is missed without dropping coverage, the owner decides before slice 5's S2.
8. **`docs/slice-4-review`** (records). Last: `knowledge/reviews/slice-4-review.md` records the review, the measurements, the follow-ups as merged and the owner's acceptances, and the roadmap records the commit that closes slice 4.

Changes 1, 2 and 3 touch different backend packages and can run in parallel with change 4 and with change 5; the forwarder branch of change 3 and change 6 run one after the other because both edit the `AGENTS.md` exception text; change 7 runs after all of them, alone; change 8 closes the slice.
